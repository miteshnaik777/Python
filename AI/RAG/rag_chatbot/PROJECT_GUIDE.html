1. Project Overview

This project implements a Retrieval-Augmented Generation (RAG) chatbot. Users upload documents (PDF, DOCX, TXT) through a web interface, and the system:

  1. Ingests files → validates, uploads to AWS S3.
  2. Preprocesses → extracts text, cleans it, splits into overlapping chunks.
  3. Embeds → converts chunks into 384-dim vectors using SentenceTransformers.
  4. Indexes → stores vectors in a FAISS index for fast similarity search.
  5. Retrieves the most relevant chunks for a user question.
  6. Generates an answer using an LLM (Groq / OpenAI / Gemini / Ollama / SageMaker).

The frontend is built with Streamlit and provides file upload, multi-turn chat, collapsible source citations, and an optional vector-visualization panel.

4. Data Flow — Step by Step

4.1 Ingestion Pipeline

Upload File → Validate → Extract Text → Clean → Chunk (500 chars, 50 overlap) → Embed (384-dim) → FAISS Index
StepModuleWhat Happens
1. Validate 01_ingestion/file_validator.py Checks extension (.pdf/.docx/.txt), non-empty, and ≤ 20 MB.
2. Extract text 02_preprocessing/text_extractor.py PDF → PyPDF2 page-by-page; DOCX → python-docx sections; TXT → decode.
3. Clean 02_preprocessing/cleaner.py Strips null bytes, normalizes whitespace, removes control characters.
4. Chunk 02_preprocessing/chunker.py RecursiveCharacterTextSplitter (LangChain) with separators: ["\n\n", "\n", ". ", " ", ""].
5. Embed 03_embedding/embedder.py SentenceTransformers all-MiniLM-L6-v2 → 384-dimension L2-normalized vectors.
6. Index 03_embedding/vector_store.py Vectors added to FAISS IndexFlatIP; saved locally under tmp/index/.

4.2 Query Pipeline

User Question → Embed Query → FAISS Search (top-5) → Build Prompt → LLM (Groq / OpenAI / Ollama / …) → Answer + Sources
StepModuleWhat Happens
1. Embed query 03_embedding/embedder.py Same model encodes the question into a 384-dim vector.
2. Retrieve 04_retrieval/retriever.py FAISS inner-product search returns the top-k most similar chunks with scores.
3. Build prompt 05_generation/prompt_builder.py Formats retrieved chunks + question into a Llama 2 chat prompt (or chat messages for external APIs).
4. Generate 05_generation/external_llm.py Sends prompt to the configured LLM provider and returns the generated answer.

5. Setup Instructions

5.1 Prerequisites

  • Python 3.10+ (3.11 or 3.12 recommended)
  • pip (comes with Python)
  • Git (optional, for version control)
  • Groq API key (free, recommended) — or another LLM provider

5.2 Install Dependencies

# 1. Open a terminal in the rag_chatbot/ folder
cd rag_chatbot

# 2. (Recommended) Create a virtual environment
python -m venv venv
venv\Scripts\activate        # Windows
# source venv/bin/activate   # macOS / Linux

# 3. Install all packages
pip install -r requirements.txt
Note: The first run will download the SentenceTransformers model (~90 MB). This only happens once.

5.3 Configure Environment Variables

# Copy the template
copy .env.example .env       # Windows
# cp .env.example .env       # macOS / Linux

# Open .env in a text editor and fill in your values

Core variables

VariableWhere to get itExample
LLM_PROVIDER Choose one: groq, openai, gemini, ollama groq
GROQ_API_KEY console.groq.com (free, no credit card) gsk_...

See EXTERNAL_LLM_SETUP.md for OpenAI, Gemini, Ollama, and other providers.

6. How to Run

6.1 Start the Chatbot (Streamlit)

# From the rag_chatbot/ folder
streamlit run 07_frontend/app.py

This opens a browser tab at http://localhost:8501. Upload documents in the sidebar, click Process Documents, then ask questions in the chat.

6.2 Run Tests

# From the rag_chatbot/ folder
python -m pytest tests/ -v

No API keys required for tests (demo LLM mode).

6.3 Visualize Vectors

# List indexed sessions
python visualize_vectors.py --list

# Visualize a specific session (opens HTML plot)
python visualize_vectors.py --session-id <id> --open

# Default: first available session, PCA
python visualize_vectors.py

6.4 Generate Problem Statement PDF

python generate_pdf.py

6.5 Quick Start Checklist

  1. Copy .env.example to .env and set LLM_PROVIDER + API key (see EXTERNAL_LLM_SETUP.md).
  2. Run pip install -r requirements.txt.
  3. Run streamlit run 07_frontend/app.py.
  4. Upload a document, process it, and ask a question.

8. Troubleshooting

Common Errors and Fixes

Error: [Errno 22] Invalid argument during ingestion (FAISS save/load) This is a Windows-specific issue with FAISS file I/O when paths contain the \\?\ long-path prefix.

Fix: Already handled in vector_store.py by the _faiss_safe_path() helper. If you still see this, ensure you’re using the latest version of the code.
Message: No LLM configured or placeholder answers only LLM_PROVIDER is empty and RAG_USE_DEMO_LLM is not set to true.

Fix: Set LLM_PROVIDER=groq and GROQ_API_KEY=... in .env, or read EXTERNAL_LLM_SETUP.md.
Error: 429 You exceeded your current quota (Gemini) Google Gemini free-tier quota is exhausted (or may be 0 in some regions).

Fix: Switch to Groq (free, no credit card): set LLM_PROVIDER=groq and GROQ_API_KEY=... in .env.
Error: 404 Model llama3-70b-8192 has been decommissioned (Groq) The default Groq model name is outdated.

Fix: Set EXTERNAL_LLM_MODEL=llama-3.3-70b-versatile in .env (already the default in the latest code).
Error: Ollama is not running The Ollama desktop application is not started, or LLM_PROVIDER is set to ollama when you intended a different provider.

Fix:
  • If using Ollama: install from ollama.com, then run ollama pull llama3.2 and start Ollama.
  • If not using Ollama: change LLM_PROVIDER in .env to your preferred provider (e.g., groq).

General Tips

Always restart Streamlit after editing .env Environment variables are loaded once at app startup. Stop the app (Ctrl+C) and re-run streamlit run 07_frontend/app.py to pick up changes.
Check your .env first Most runtime errors are caused by missing or incorrect values in .env. Compare your file with .env.example to ensure all required keys are present.
